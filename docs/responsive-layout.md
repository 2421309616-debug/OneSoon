# 全局布局与适配

当前适配目标是移动端 H5、平板和桌面浏览器。样式入口是 `apps/passenger/src/App.vue`，统一加载 `src/styles/layout.css`。所有页面默认全宽，不再使用 375px 的页面最大宽度。

## 规则

| 窗口宽度 | 页边距 / 区块间距 | 内容区块列数 | 小应用列数 |
| --- | --- | --- | --- |
| 小于 768px | 8px | 1 | 4 |
| 768–1199px | 16px | 2 | 6 |
| 至少 1200px | 24px | 3 | 8 |

区块网格通过 `.app-section-grid` 显式启用；普通页面保持自然纵向布局。网格内要占满一行的模块使用 `grid-column: 1 / -1`。

- `--app-viewport-height` 优先使用 `100dvh`，不支持时回退 `100vh`。
- 四边安全区统一通过 `--app-safe-*` 读取；不要在各页重新计算同一组 inset。
- 导航内容高 56px，边框 1px，另加底部安全区。固定底栏与页面占位共同使用 `--app-nav-height`，修改导航高度时只改全局变量。
- 正文使用 16px，小字使用 12px；交互目标至少 44px。容器扩展时不按桌面窗口宽度无限放大字体或按钮。
- `pages.json` 的 `rpxCalcMaxDeviceWidth` 和 `rpxCalcBaseDeviceWidth` 都保留为 375，只控制已有局部图标、圆角等 `rpx` 的缩放上限，并不限制页面宽度。新增关键字号和触摸高度优先使用共享变量。
- 高度不超过 500px 时，首页改为自然布局并在页面内滚动，停用拖动和卡片吸顶，避免横屏和软键盘压缩高度时与底栏重叠。高度恢复后重新测量。
- 地图预留区的灰色是应用内部背景，与窗口两侧留白无关。

## 新增页面

常规页面使用下面的结构，内容区自动预留安全区和固定底栏高度：

```vue
<template>
  <view class="app-page">
    <view class="app-content app-content--with-nav">
      <view class="app-card">页面内容</view>
    </view>
    <BottomNav current="profile" />
  </view>
</template>
```

没有底部导航时移除 `app-content--with-nav` 和 `BottomNav`。需要固定可视高度时加入 `app-page--viewport`，并自行明确内容的滚动容器。普通页面不要设置固定高度或 `overflow: hidden`。

`.app-card` 只负责最小宽度、底色和圆角，内边距按内容使用 `var(--app-card-padding)`。不要对 `view`、图片和所有组件统一强制 `width: 100%`，否则会破坏局部布局。

## 验证

至少检查 320×568、375×812、430×932、844×390、768×1024、1440×900，以及宽度断点 767/768、1199/1200、高度断点 500/501。检查页面和底栏全宽、无横向溢出、展开到底后末尾可见，以及切换页面、旋转和调整窗口后的面板位置。

这些规则提供 H5 响应式布局，不代表已完成小程序或原生 App 的运行时兼容。首页的浏览器 API 仍需在迁移平台时替换或添加条件编译；Safari、微信内置浏览器和真机安全区需另做真机回归。
