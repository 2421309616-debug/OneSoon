# 派单设计

日期：2026-11-08

> **⚠️ 本文已被取代，只作历史记录。**
>
> 现行方案见 [`2026-11-15-dispatch-strategy.md`](./2026-11-15-dispatch-strategy.md)。
> 主要变化：半径分波改成按接驾时间分 A/B/C/D 四档；加权随机改成就近排序 + tiebreak；
> 一次推 1 人而不是 3 人；推送节奏 15 秒 tick / 30 秒换人 / 60 秒过期；加了抢单防护。

---

## 每一波是什么

三层漏斗每跑一次，就是一个「波次」。一轮派单由四个波次组成，由近及远往外找：

| 波次 | 半径 | 时长 | 每波推送 |
|---|---|---|---|
| 第 1 波 | 2 km | 15 秒 | 3 人 |
| 第 2 波 | 4 km | 15 秒 | 3 人 |
| 第 3 波 | 7 km | 15 秒 | 3 人 |
| 第 4 波 | 10 km | 15 秒 | 3 人 |

四波走完合计约一分钟。之后进入边缘加价（见下）。

**为什么分四波而不是一步到位**

固定范围在车少的时候永远找不到；一步用大范围，又会把二十公里外的车召唤过来，乘客等更久。由近及远逐波扩大，是在「尽快找到」和「车别太远」之间取平衡。

半径不是每波翻倍（2/4/8/16），因为翻倍到后面覆盖面积过大，最后一波会召唤到跨镇的车。后三波按 ×2、×1.75、×1.4 递减扩张，恰好补偿越往外司机越稀的密度差。

**为什么每波推 3 个人**

推 1 个，四波只有 4 次机会，司机在忙就漏掉了；推 8 个，等于变相广播，又回到了抢单市场。3 个够用，且几个人同时收到同一单时，先点的人拿到，其余人的推送立刻作废。

## 三层漏斗

每一波派单都走同一套漏斗，依次回答三个问题。前一层没有通过，就到不了下一层。

```
                候选全集：系统里所有司机
                          │
        ┌─────────────────▼─────────────────┐
        │ 第一层 · 资格过滤                   │
        │ 不满足硬条件直接出局                 │
        └─────────────────┬─────────────────┘
                          │  合格司机
        ┌─────────────────▼─────────────────┐
        │ 第二层 · 就近分档                   │
        │ 按 ETA 分档，只取最靠前的非空档        │
        └─────────────────┬─────────────────┘
                          │  候选档
        ┌─────────────────▼─────────────────┐
        │ 第三层 · 加权随机                   │
        │ 服务分 × 空闲因子，随机抽取           │
        └─────────────────┬─────────────────┘
                          │
                    被推送的司机
```

**第一层 · 资格过滤（硬条件）**

只要有一条不满足，就直接排除：已出车且处于听单状态、手上订单未超上限、落在当前波次半径内、这一单没有推送过该司机。

这一层只回答「能不能」，不打分（本层用于筛掉不符合资格的司机）。

**第二层 · 就近分档（硬优先级）**

按预计到达时间（ETA）分档，越快到的一档越优先，前一档没人了才看下一档。

之所以用 ETA 而不是「本波内的相对排名」，是因为乘客关心的是「多久能到」；同样快的人，不该因为落在哪一波就成了两种待遇。

之所以用 ETA 而不是直线距离，是因为距离本身没有意义，换算成「乘客要等多久」才有意义。当前还没有路况数据，ETA 按「直线距离 × 道路曲折系数 ÷ 区间均速」估算；将来接入真实导航或路况，只换估算方式，分档阈值不用动。

参考档位：

| 档位 | 预计到达 | 约合直线距离（30 km/h、曲折系数 1.3） |
|---|---|---|
| A | ≤ 3 分钟 | ≤ 1.15 km |
| B | 3 ~ 6 分钟 | 1.15 ~ 2.3 km |
| C | 6 ~ 12 分钟 | 2.3 ~ 4.6 km |
| D | > 12 分钟 | > 4.6 km |

A 档之所以定在 3 分钟，是因为三分钟内到的司机乘客几乎不用等；这时候优先「快」不会伤害公平。超过 3 分钟，差一两分钟对乘客差别不大，就该让服务分说话了。

同一波里若最靠前的档人数不足，从次近的档补，不会为了凑人数跳过已有候选。

**第三层 · 加权随机（软倾向）**

同档内距离已无区别，于是按权重分配概率、随机抽取，而不是权重高的必定胜出。

```
权重 = 服务分^1.7 × 空闲因子
```

**服务分**只影响被选中的概率：服务好的多接一些，但谁都有机会，避免高分者赢家通吃、新人永远没机会。按 1.7 次方做轮盘赌，同档内 5.0 / 4.9 / 4.8 三人的中签概率约为 34.5% / 33.3% / 32.2%（严格排序则是 100% / 0% / 0%）。

**空闲因子**补偿长时间没被派到的司机。它不看绝对时长，而是看**同档内的相对位置**：把同一档的候选按「上次被推送距今」排序，按人数均分成三组。

| 位置 | 空闲因子 |
|---|---|
| 最久没被推送的 1/3 | 1.2 |
| 中间 1/3 | 1.0 |
| 最近被推送过的 1/3 | 0.8 |

之所以用相对位置而不是绝对时长，是因为绝对时长没有参照系：60 分钟算不算久，取决于这段时间里他被推送过几次。被推过二十次却一直拒单，那不是冷落；一次都没被推过，才是。

这么改还顺带堵住一个漏洞：如果按绝对时长补偿，一个服务分偏低、但挂机很久的司机，权重能压过服务分中等、刚被派过的司机——等于鼓励「靠挂着等」洗白服务分。按相对位置排，他想翻盘就必须持续排在同档最闲的那一组，而他进入候选的机会本来就少，自然形成阻尼。

**因子跨度与服务分跨度的关系**：因子最大跨度是 1.2 ÷ 0.8 = 1.5，服务分从 4.2 到 4.9 的跨度是 1.30，两者接近但不相等。极端情况下——最低分的司机恰好排在最闲组、最高分的恰好排在最近组——低分司机仍能短暂反超，幅度约 15%。这是有意保留的取舍：要完全消除翻盘，因子必须压到 1.1 / 1.0 / 0.9 以内，那时补偿几乎等于没有。

空闲从**上次被推送订单**起算，不是从上次接到单起算。司机被反复推送却一直拒单，那是他自己不要，不算没单可跑。

同档人数不能被 3 整除时，多出来的名额给靠后的组，宁可少补偿，也不要把「最近刚被推送过」的人误判成被冷落。

## 服务分从哪来

第三层依赖服务分，但服务分本身怎么定，需要单独说清：

- **不是终身累积**，而是最近一段时间评价的滚动平均。终身累积会让分数固化，高分者永远高分，反而成了「一家独大」的燃料
- **新司机从略低于平均的分数起步**（建议 4.8），不是满分。满分起步等于新人一进来就顶格
- **长期不跑单的司机会向下回归**，防止「很久以前的老号挂着高分压制所有现役司机」
- 第一期只用一个维度（乘客评价），后续再拆成完单率、应答率、在线时长

**第一期的现实**：还没有评价体系，所有人分数相同，服务分这一项退化掉，此时权重差异完全来自空闲因子——这恰好是第一期真正能起作用的那一半。

## 边缘加价结构

四波走完仍无人接，说明这个半径内确实没有车。此时给乘客一个加钱扩大范围的机会。

```
四波走完，无人接单
        │
        ▼
   加价第 1 档
        │
   ┌────┴────┐
   │同意      │拒绝
   ▼         ▼
扩大半径    保持原半径
再找一轮    继续搜索
   │         │
   ▼         │
仍无人接     │
   │         │
   ▼         │
加价第 2 档 ◄┘（订单一直挂着，随时可再加价）
   │
   ▼
加价第 3 档
   │
   ▼
三档都试过仍无人接 → 不再弹窗，订单继续挂着等
                     乘客可随时手动取消
```

建议档位：

| 档位 | 加价 | 半径扩到 |
|---|---|---|
| 第 1 档 | +3 元 | 13 km |
| 第 2 档 | +6 元 | 16 km |
| 第 3 档 | +10 元 | 20 km |

原则：

- 分三档逐步加深，不一次性加到顶
- **乘客拒绝后保持原半径继续搜索**，既不取消订单，也不停止派单
- 加价后只找一轮，因为半径已经很大，再分波没有意义
- 三档试完就停止弹窗，但订单不取消

加价是选项，不是强制。乘客可以一直拒绝、一直等，也可以随时取消；系统不会替乘客做「叫不到车」的决定。

## 派单结果落到哪

派单的每个结果，最后都要落到订单状态上：

| 状态 | 含义 | 由谁进入 |
|---|---|---|
| 寻找司机 | 四波、加价、挂单都停在这个状态 | 系统 |
| 前往上车点 | 司机已接单 | 司机 |
| 等待上车 | 已到上车点 | 司机 |
| 行程中 | 乘客已上车 | 司机 |
| 结算 | 到达目的地 | 司机 |
| 已完成 | 确认收款 | 司机 |
| 已取消 | 取消订单 | 乘客 |

司机接单后如果想放弃，订单**回到「寻找司机」**，从第 1 波重新开始（该司机本单排除），而不是直接作废——这样乘客无感。

---

## 遵守规则

**一个订单对同一个司机只推一次。** 不管是拒绝了还是没看见（推送超时），这份订单都不会再推给他第二次，避免反复骚扰同一个人。

**司机可以同时收到多份不同订单的推送。** 每份推送各自独立、各自计时，接其中一单不影响其它几单。

## 服务分演进：先 1+2，后续加 3

三层漏斗里，前两层是硬规则，第三层才用到服务分。服务分的参与方式有三条路：

| 方案 | 做法 | 结论 |
|---|---|---|
| 1 · 分层分档 | 不同距离档之间有硬优先级 | **第一期** |
| 2 · 加权随机 | 同档内按分数给概率随机抽取 | **第一期** |
| 3 · 多维服务分 | 评价 + 完单率 + 应答率 + 在线时长 | **后续叠加** |

**方案 1 · 分层分档**

不同距离档之间有硬优先级：A 档还有人，就不看 B 档；A 档没人了才轮到 B。距离近的人永远排在距离远的人前面，服务分再高也越不过这一层。

它保证的是乘客体验：公平不能让乘客多等一个档位。

**方案 2 · 加权随机**

同档内距离已经没有区别，于是按服务分分配被抽中的概率，而不是分数高的必定胜出。

5.0 分的司机不保证赢，4.8 分的也不保证输，只是 5.0 分的概率更大——按 1.7 次方的权重关系，三人同档时大约是 34.5% / 33.3% / 32.2%。

它保证的是司机公平：不让好司机赢家通吃，也不让新司机永远接不到单。

**方案 3 · 多维服务分**

把服务分从「一个数字」换成「四个维度」：乘客评价、完单率、应答率、在线时长。

单一维度容易被钻空子——比如只挑好跑的单来维持高分；多个维度互相牵制，跑得多的、接得勤的、被投诉少的都算数。

它需要评价表、行程回调、应答统计这些基础设施，第一期还没有，所以放到后面。

第一期 = **1 + 2**：分层分档保证「近的一定优先」，加权随机保证「同档内不一家独大」。

后续 = **1 + 2 + 3**：漏斗结构不动，只把第三层的服务分从单一维度换成多维。
